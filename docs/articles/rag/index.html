RAG 的定义

Retrieval-Augmented Generation（检索增强生成）在生成答案前或过程中，先取得相关外部资料，将其作为模型上下文。它改变推理时可见的信息，并不自动改变模型参数；与 fine-tuning（微调）的作用不同。

处理链路

离线阶段通常包含文档清洗、切分、元数据和索引；在线阶段包含查询处理、检索、可选 reranking（重排）、上下文组装与回答。Chunk 的大小与重叠需要兼顾语义完整性、检索粒度与上下文预算。

Embedding、关键词与重排

Embedding 将内容表示为向量，以相似度寻找语义相关资料；关键词检索擅长精确术语和编号。混合检索组合不同信号；重排对候选进行更细的相关性判断。相似度高不代表事实正确、资料新或调用者有权限读取。

评估与常见误区

检索评估关注正确资料是否进入候选及排序；回答评估关注是否基于证据、是否完整、引用是否支持结论。无相关证据时应表达缺失，不能用无关引用装饰答案。权限过滤与来源更新时间也影响可用性。

认知模型：证据流与决策流

RAG（Retrieval-Augmented Generation，检索增强生成）把外部证据接入生成过程。它有离线/增量索引链和在线问答链：前者决定什么可被找回，后者决定本次查询实际拿到什么、交给模型什么以及如何表述答案。模型会流畅回答，不代表证据链完整。

documents -> parse -> chunks + metadata -> embedding / search index
query -> candidate retrieval -> fusion / reranking -> selected context
                                                     -> answer + citations

Chunk（片段）是检索与组装上下文的单元，document（文档）是来源与语义组织单元，两者不一定一一对应。Metadata（元数据）记录来源、版本、时间和访问范围；没有元数据的高相似度片段，可能来自过期文档或无权限材料。

检索组件各解决什么问题

Dense retrieval（稠密检索）用 embedding（向量表示）寻找表示空间中的近邻，适合捕捉某些语义关系；sparse retrieval（稀疏检索）利用词项特征，常有利于精确词、编号和术语。相似度不是事实正确率，也不是相关概率。

Hybrid retrieval（混合检索）组合不同候选来源。RRF（Reciprocal Rank Fusion，倒数排名融合）根据排名融合，不要求不同搜索器分数处在同一尺度；reranker（重排器）重新评估候选与查询的匹配。重排不能找回根本没有进入候选集的关键文档。

Chunking（分块）存在权衡：过小可能割裂定义与条件，过大可能引入噪声、挤占上下文。Overlap（重叠）减少边界割裂，但也增加重复和索引成本。适合代码、表格或长文的分块策略可能不同，不能只选一个字符数当作通用答案。

把失败归因到可观察的一层

结果先检查
文档完全找不到是否成功解析/索引、版本和过滤条件
候选不相关查询表达、搜索器与候选召回数量
候选有证据但上下文没有融合、重排、截断和去重策略
上下文有证据但答案错误条件理解、生成约束、引用与忠实度
回答了没有证据的问题无证据时的拒答、澄清和外推边界

Retrieval recall（检索召回）衡量需要的证据是否进入候选；answer faithfulness（答案忠实度）关注回答是否由给定证据支持；answer correctness（答案正确性）还需要对照问题与真实答案。仅检查答案是否包含引用链接不足以证明它引用得对。

更新、权限与可信度

来源变更后，要让新版本进入索引并处理旧片段；否则“最新页面”与“检索到的缓存”会冲突。权限过滤必须作用于候选获取和上下文选择，不能只在最终界面隐藏链接。检索文档是证据，不应变成修改系统行为的指令。

面试回答：RAG 能消除幻觉吗？ 它增加可追溯证据，但仍受解析质量、召回、上下文选择和生成忠实度影响。应通过包含有答案、无答案、过期与冲突来源的代表性查询集分别评估各环节，结合 Agent 执行边界 讨论工具和权限。

简答与面试回答参考

答案不准确时为什么先查检索？ 模型可能根本没看到需要的证据。应分别定位资料、切分、召回、排序、上下文和生成，避免把所有失败归结为 prompt。
